# Evidence-led LaTeX publication

Apply automatically when the task requires scientific writing or a paper; use the configured shell and file tools without asking the user to name skills. Continue within existing user scope. Deliver illustrated, professionally composed actual LaTeX: full-width title, two-column body, narrow edge floats and wide top floats unless a specific target journal requires another form. Retain verified bibliography, source figures/data and claim evidence. Formatting never supplies findings or establishes scientific validity.

1. Inspect the actual question, source reading depth and results. Automatically load and apply the [bundled ARIS/Nature/Scholar workflow](references/upstream-workflow.md) through the catalog for plan, section-by-section writing, figures, citations and review, using the configured model. Use [scripts/scaffold_manuscript.py](scripts/scaffold_manuscript.py) for evidence quote/artifact validation; it is evidence staging, while the publication CLI owns final typesetting. Preserve real evidence fields in the manuscript claim register. Never invent findings or citations.
2. Read [template selection](references/templates.md) and [publication CLI](references/publication.md). Choose the target venue's requirements; absent a target, proceed with two-column `neutral`. Run `python scripts/publication.py init manuscript --title "Actual study" --template neutral --language en` into a new directory. Use `zh` or `bilingual` for Chinese and `nature-inspired` or actual `ieee` when appropriate. `--demo`/`--layout-demo` create invented build fixtures, never study evidence.
3. Draft `main.tex`, `references.bib` and `claims.csv` from real evidence. Read [figure, equation and claim rules](references/figures-equations.md). Use aligned mathematics, units, booktabs and editable vector PDF/SVG where suitable. Narrow floats require `[t]`/`[b]`/`[tb]`; wide floats require `[!t]`. Inline `[h]`/`[H]` is rejected. Record exact independent-unit counts and error definitions. Verify source support and bibliography, then resolve unknown/ARIS markers or report an unfinished draft.
4. Run the copied project CLI: `python publication.py doctor .`, `check .`, `compile .`, `check . --require-compiled`, then `render .`. Missing engines/packages/fonts/renderers are `needs-setup`; retain source and diagnostics. Never substitute a fake PDF, silently switch engines or claim success from source presence. Compilation disables shell escape and automatic MiKTeX installation, runs bounded real TeX/BibTeX and retains exact commands/logs. The helper accepts trusted sources; use the configured OS sandbox for untrusted TeX.
5. Inspect every rendered page and fix clipping, overfull content, unreadable figures, missing glyphs and reference diagnostics; rebuild and render after source changes. Checkpoint actual source, bibliography, claim register, analysis/figure inputs, vectors, PDF, logs and render/compile reports through `science_project` using its current revision. Advance only after a successful checkpoint and an honest evidence assessment. Report the build status, visual review and scientific limitations separately; setup failure is incomplete delivery, not successful publication.
